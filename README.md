# 明鉴：AI 时代的信息核查训练场

> **不是替你判断真假，而是训练你找到证据。**

《明鉴》是一套面向大学生及普通网络信息使用者的**交互式信息素养训练工具**。用户在 8 个虚构的网络信息情境中，亲自检查来源、追溯原始语境、对比证据、辨别数据表达，并在作出判断后获得可解释的反馈与个人学习报告。

- **形态**：纯前端 Web 应用，React + Vite + TypeScript，可静态部署，**无需后端、无需联网**。
- **目标用途**：2026 年第十四届全国大学生数字媒体科技作品及创意竞赛，自主选题类「智慧教育与科普创作类」赛项。
- **全部案例均为虚构教学模拟**，不对应任何真实事件、机构或个人。

## 一、快速开始

### 环境要求

- Node.js **18.x 或更高**（本项目在 **Node.js v22.22.2** 下完成安装、类型检查、测试与构建验证）
- npm 10.x（随 Node 附带）

### 安装与运行

```bash
npm install     # 安装依赖
npm run dev     # 启动开发服务器（默认 http://localhost:5173）
npm run build   # 类型检查 + 生产构建，产物输出到 dist/
npm run preview # 预览生产构建（默认 http://localhost:4173）
```

其他命令：

```bash
npm run typecheck  # 仅运行 TypeScript 类型检查
npm test           # 运行单元测试（Vitest，共 71 个用例）
```

### 关于 npm 源

仓库内已包含 `.npmrc`，将 registry 指向 `https://mirrors.cloud.tencent.com/npm/`。
这是为了在默认源（`registry.npmmirror.com`）返回 502 的网络环境下完成安装。
**如果你的网络可以直连官方源，请把 `.npmrc` 里的 registry 改为 `https://registry.npmjs.org/` 或直接删除该文件。**

### 静态部署

构建产物在 `dist/`，可直接托管到任意静态服务器（GitHub Pages、Gitee Pages、Netlify、Vercel、对象存储等）。

- 若部署在**根路径**：保持 `vite.config.ts` 中 `base: "/"` 不变。
- 若部署在**子路径**（如 `https://example.com/mingjian/`）：把 `base` 改为 `"/mingjian/"`。
- 深链刷新（如直接打开 `/case/C03`）需要服务端配置 SPA fallback：把所有未匹配路径回退到 `index.html`。
  仓库已附 `public/_redirects`（Netlify 规则）；其他平台请自行配置等价规则。
  `npm run preview` 已内置该回退，可直接验证。

## 二、功能页面与路由

| 路由 | 页面 | 核心职责 |
|---|---|---|
| `/` | 首页 / 调查室 | 项目主张、开始 / 继续入口、进度摘要、三项能力条目、模拟声明 |
| `/?guide=1` | 玩法说明 | 三步讲清「这是什么 / 怎么玩 / 怎么算分」，页眉可随时重看 |
| `/tutorial` | 独立引导关 | 六步图形化教学关，每步都要真实操作才能继续；不计入任何成绩 |
| `/assessment/pre` | 训练前测 | 5 题（结论 10 分 + 行动 10 分），建立真实基线 |
| `/missions` | 任务地图 | 8 个案例的难度、技能标签、状态与解锁条件 |
| `/case/:caseId` | 核查工作台 | 主张 → 证据 → 核查步骤 → 结论 / 把握程度 / 行动 → 提交 → 反馈 |
| `/assessment/post` | 训练后测 | 5 道平行题，与前测能力结构相同、题面不同 |
| `/report` | 学习报告 | 案例表现、四项维度、能力维度、前后测变化、优势与建议 |
| `/about` | 项目说明 | 教育目标、核查方法、虚构声明、数据隐私、功能边界、参考资料 |

未知路由显示友好 404；未知或锁定 caseId 会重定向回任务地图并给出提示。

## 三、3—5 分钟演示路径

0. 首次进入会自动弹出**玩法说明**（3 步，约 30 秒）；最后一步可直接进入**引导关**。
   建议新用户先走 `/tutorial`：**六步卡片总览 → 逐步实操（读主张 / 查证据 / 建证据链 /
   做核查 / 下结论 / 选行动，每步未完成不能进入下一步）→ 提交后查看逐项反馈**，约 3 分钟。
   引导关不计入任务解锁、学习报告与前后测。
   进入正式案例后，顶部还有一条**分步提示条**，会随作答进度自动推进，可随时「收起」。

1. 打开首页，点击 **开始训练** → 完成 5 道前测（提交后可见真实得分）。
2. 进入 **任务地图**，点击 **C01 一张正式的停课通知截图**。
3. 在核查工作台中：
   - 左栏阅读**待核查主张**；
   - 中栏逐条点击证据卡的 **查看详情**（查看模拟截图 / 官网列表 / 课程系统 / 评论区），
     并把你认为关键的材料 **加入证据链**；
   - 勾选 **核查步骤清单**（必须手动勾选，系统不会代劳）；
   - 右栏选择 **结论**、拖动 **把握程度滑块**、选择 **下一步行动**；
   - 点击 **提交结论**。
4. 查看反馈：总分与四项维度分、标准结论、命中的关键证据、遗漏的关键证据、
   易误用材料解释、核查步骤逐条反馈、信心校准提示、建议核查路径、可迁移原则。
5. 点击 **继续下一案**，或回到任务地图完成更多案例；全部 8 个案例完成后做**后测**，
   最后打开**学习报告**查看真实前后测变化。

> 评审可用首页的「跳过前测，进入演示模式」按钮直接开放全部案例；
> 演示模式下的作答不计入正式前后测数据，会在页面顶部持续标注。

## 四、技术实现

### 目录结构

```text
mingjian/
├─ public/
│  ├─ favicon.svg
│  └─ _redirects                  # 静态部署 SPA fallback（Netlify 规则）
├─ src/
│  ├─ app/
│  │  ├─ App.tsx                  # 应用外壳：页头、路由、页脚、存档提示
│  │  └─ ProgressProvider.tsx     # 全局进度状态 + localStorage 同步
│  ├─ components/                 # Icons / ProgressBar / ClaimCard / EvidenceCard /
│  │                              # EvidenceDrawer / EvidenceMockView / Checks /
│  │                              # FeedbackPanel / ReportCharts / EmptyState / AppHeader
│  ├─ pages/                      # Home / Tutorial(引导关) / Assessment(pre,post) /
│  │                              # MissionMap / CaseWorkspace / Report / About / NotFound
│  ├─ data/
│  │  ├─ cases.ts                 # C01—C08 全部案例内容（虚构教学模拟）
│  │  ├─ tutorial.ts              # 引导关专用案例 T00（不计入成绩）
│  │  ├─ pretest.ts               # 前测 A 卷
│  │  └─ posttest.ts              # 后测 B 卷
│  ├─ engine/                     # 纯函数：scoring / progression / report / validation /
│  │                              # tutorial（引导关步骤引擎）/ guide / shuffle
│  ├─ storage/progressStore.ts    # localStorage 读写、版本、异常兜底
│  ├─ styles/                     # tokens.css / global.css / motion.css /
│  │                              # editorial.css / tutorial.css
│  ├─ types/index.ts              # 全局类型定义
│  └─ main.tsx
├─ tests/                         # 评分、解锁、报告、渲染冒烟测试
├─ README.md
├─ package.json
└─ vite.config.ts
```

### 关键技术点

- **架构**：React 18 + React Router 6 + TypeScript（strict）；设计 token + 普通 CSS，无 UI 框架。
- **图表与图标**：全部使用原生 SVG 与 CSS 自绘（`components/Icons.tsx`、`EvidenceMockView.tsx`），
  不依赖任何图标库、图表库或外部图片服务。案例中的「截图 / 照片 / 图表 / 音频」都是界面示意。
- **评分引擎**（`engine/scoring.ts`，严格按文档第 7 章）：

  | 维度 | 分值 | 判分依据 |
  |---|---:|---|
  | 结论判断 | 30 | 与标准结论（或 `acceptableLabels`）一致 |
  | 证据选择 | 35 | `clamp(round(35 × 关键证据命中率) − 8 × 已选干扰证据数, 0, 35)` |
  | 核查步骤 | 25 | `round(25 × 已完成步骤数 / 步骤总数)` |
  | 下一步行动 | 10 | 案例配置中的 `points`（0 / 5 / 10） |

  把握程度（0—100%）**单独记录，不计入 100 分**，只在反馈中用于对照「信心与证据是否匹配」。
  单元测试覆盖了：全部正确、漏选关键证据、选中干扰证据、结论错误、行动不当、
  未完成步骤、全空提交、重复计分、分数上下界等情形。

- **任务解锁**（`engine/progression.ts`）：C01 始终可进入；完成 1 个案例后开放 C02；
  **完成任意 2 个案例后开放其余全部案例**，确保用户不会被永久卡住。解锁只看完成状态，不看分数。
- **报告聚合**（`engine/report.ts`）：案例默认采用**最佳成绩**（可切换查看最近一次），
  重做会追加历史记录而不覆盖首次成绩；技能维度只统计「已完成且携带该标签」的案例，
  样本少于 2 个时提示样本不足；未完成的测验显示「尚未完成」而**不用 0 分伪装**。
- **本地存档**（`storage/progressStore.ts`）：`localStorage` 单键 `mingjian.progress.v1`，
  带 `schemaVersion`；JSON 解析失败、字段缺失、版本不符、写入配额异常均有兜底与可见提示，绝不白屏。
- **可访问性**：键盘可遍历全部流程，`focus-visible` 清晰，抽屉支持 Esc 关闭与焦点回流，
  表单错误提示靠近对应字段并带 `role="alert"`，状态不只靠颜色表达（图标 + 文字 + 颜色），
  支持 `prefers-reduced-motion` 与应用内「减少动效 / 大字号」开关，移动端点击目标 ≥ 44px。
- **响应式**：1440 / 1024 / 768 / 390 / 320px 均已按布局设计处理；
  桌面为三栏工作台（≤1180px 退化为两栏，≤860px 单栏），
  移动端按「主张 → 证据 → 已选证据 → 核查步骤 → 结论与行动 → 提交」纵向堆叠，底部固定提交栏不遮挡正文。

### 数据与隐私

- 所有进度保存在**本机浏览器 localStorage**，主键 `mingjian.progress.v1`；
  **不上传任何答题记录**，不采集姓名、学号、手机号、位置等个人信息。
- 没有服务器、账号、云端同步、排行榜；断网后 8 个案例的核心流程完全可用。
- 「清空本机记录」需二次确认，只删除明鉴自身的存档键，不影响其他网站数据。
  也可在 `/about` 页面或报告页执行。
- **试用数据导出**：报告页底部可导出 `mingjian-trial-*.json`，
  内容只含分数、完成状态与技能维度统计，**不含姓名、账号、设备标识与具体作答文本**，
  且不会上传任何服务器，由试用者本人决定是否交给组织者。

### 组织一次真实试用

1. 试用者在自己浏览器完成训练（至少完成前测 + 若干案例）。
2. 在「我的学习报告」页底部点击 **导出本次试用数据（JSON）**，把文件发给你。
3. 把所有 json 放进 `trial-data/`（目录内已有说明）。
4. 运行汇总脚本：

```bash
npm run trial:aggregate      # 读取 trial-data/*.json，输出统计并写入 trial-data/summary.md
```

脚本只统计真实文件：目录为空时明确输出「尚无用户测试数据」，不生成任何占位数字；
不做显著性检验，前后测变化只作为观察性结果描述。

### 防「送分」设计

为避免玩家靠位置或措辞猜答案：

- 结论选项、行动选项、证据卡的呈现顺序都按案例 id **确定性打乱**（`src/engine/shuffle.ts`），
  同一案例每次打开顺序一致，可复现、可测试；
- 行动选项统一为中性、长度接近的日常表述，不再出现「暂停转发」「不扫码」这类自我标注；
- 界面上不再对 0 分选项显示「高风险」标签，风险判断交给玩家自己完成；
- **证据角色与分析延后揭晓**：提交前，证据卡不显示「易误用材料 / 关键证据」，
  证据详情也不展开「这条材料能支持什么 / 它不能单独证明什么」，只显示一个「提交后揭晓」占位块；
  提交后反馈页新增「回看全部材料」，此时才显示角色标记，并可点开完整分析（回看模式不可改答案）。

## 五、项目边界（本产品明确不做的事）

- 不接入实时 AI 图片 / 音频 / 视频鉴伪接口，**不宣称能够自动鉴定现实内容的真假**。
- 不接入后端、数据库、用户账号、云端同步或在线新闻爬取；不使用大模型自由对话。
- 不把「图片看起来奇怪」「疑似 AI 痕迹」单独作为判断内容真假的充分证据。
- 不把「没有查到证据」自动等同于「是假的」。
- 不仿冒真实学校、政府或机构的官方页面；不使用未经授权的真实肖像、声音或素材。
- 不编造案例结果、用户人数、前后测提升幅度或测试报告。
  报告页在无真实试用数据时明确显示 **「尚无用户测试数据」**。

## 七、提交前需要人工完成的事项

1. **真实试用测试**：邀请 5—10 名目标用户实际操作，记录人数、完成率与反馈。
   **在没有开展试用前，不得在任何材料中填写人数、完成率或提升百分比。**
2. **截图**：首页、任务地图、证据详情抽屉、案例提交反馈、学习报告、移动端布局（建议 390px 与 320px 各一套）。
3. **演示视频**：建议 3—4 分钟，从首页开始连续演示至少一个完整案例闭环、前后测与报告、存档与响应式。
4. **材料核对**：以竞赛官网（https://www.cmit.cn/ ）最新通知、《作品材料提交规范》与《评分标准及奖项设置》为准，
   核对提交格式、文件大小、视频时长与上传入口。
5. **原创性与 AI 使用说明**：如实说明哪些内容由 AI 工具辅助生成、哪些由作者设计、编辑与核验。
